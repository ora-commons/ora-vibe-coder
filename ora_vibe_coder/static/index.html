    Welcome to Ora Vibe Coder

    Vibe finds your projects automatically inside your Documents folder. This page belongs to the supplied installer; ordinary use starts from the Ora Vibe Coder launcher.

    Python 3.10 or later runs this local interface. Your coding tool handles conversations, account login, and approvals.

    Ora AI Boost (Gear 3 and Gear 4) is bundled with Vibe as an optional aid for Specification and Planning — Vibe works without it, and setup installs its reviewed runtime beside the application.

    Working with Ora Vibe Coder

    Vibe searches this installation's configured projects folder, or your Documents folder when none is configured, for projects with a Project.md definition. The header's first row holds step 1 with New and Open and the project picker — opening the picker refreshes the list first, and a failed refresh keeps the last list with a notice that it may be out of date. The second row holds step 2 Details, one view that shows and edits every saved project field, the status bar, and More. The third row holds step 3 Coding tool with its readiness and Recheck, the stage title, and Configure Path and Run to Completion, in every workspace. On a narrow window one pane shows at a time beside the branded spine; Show document and Show conversation switch between them, and panes are never stacked.

    The status bar reports the last action or the operation under way, with elapsed time and last Bridge contact while work runs. Progress is never claimed because time passes. More holds secondary detail only: tool caveats and readiness facts, the last turn's saved-file readback and Bridge diagnostics, the saved request location with Copy path and manual Copy, the desktop-app route, and the optional external review file.

    Step 4 works on the active stage: your text, up to ten pictures and up to ten selected Markdown or text files go together through the selected tool; the complete answer appears when the turn finishes. When a reply ends with a Questions for you section, its bare bullets appear as Answer to continue above the response box; write your answer and press the send button. Nothing is shown when the reply asked no question. When a turn saves the stage document without asking anything, the status bar points to the Review step. Copy stage request for another AI prepares the same request without saving.

    Step 5 Review has its own Reviewer picker, independent of the step 3 coding tool: it starts out matching it, then the two choices never change each other. The saved verdict shows as PASSED, NOT PASSED or NOT REVIEWED; an earlier-version marker stays when the document changed after its review. An unclear record gets one brief read-only judgment, remembered per content; a failed call shows a reading error, never an unclear verdict. With Second opinion the Reviewer assesses, a peer harness you choose evaluates, and the Reviewer revises, optionally iterating to agreement. Beside Review the Plan, Approve the Plan is greyed out until the current Plan review is COMPLETE; clicking it saves Status: APPROVED in the Plan itself, preserving the rest of the document and its review. It makes no AI call and starts nothing.

    When a review is INCOMPLETE or a Verification Report is NOT PASSED, one read-only call sorts the findings into AI can fix and Needs your input. AI Work then shows Request repairs and the questions; both can apply together, and the review box keeps its verdict with a short pointer. A failed sorting shows as a failed sorting with Retry — never as a verdict, a repair or an invented question.

    Step 6 delivers the next stage with one click: Send to <tool> prepares and saves the complete request — including your unsent step 4 text and attached files — then starts the next stage's turn here; Copy request prepares, saves and copies it (pictures are named, not carried). For Hermes and Qwen Code the primary button is Open in Terminal; the status bar says the request was opened, not that it was received. The saved path, Copy path, manual Copy and the desktop route live under More. Before implementation stays advisory and never blocks.

    Build & Verify: step 5 saves a truthful Programming Result, step 6 arranges fresh independent verification, step 7 sends a completed report's repairable findings back for correction. The saved report gives the verdict — PASSED, NOT PASSED, REVIEW INCOMPLETE or NOT VERIFIED — and the next action follows it: NOT PASSED offers Request repairs; REVIEW INCOMPLETE offers to finish or rerun verification. An older passing report never counts for newer code. The composer stays available in every state.

    Run to Completion runs the fixed route — Specification, Plan, Build, independent verification, then Correction and back to verification — from the stage you are in, without redoing earlier stages. Clicking Run saves your unsent text and files as the run's brief and clears them; a failed brief save keeps it for retry. The run pauses for questions (the composer answers them), for operational failures (with a Copy request fallback), and can show a skip-review warning that Settings can turn off. Three attempts without progress end the run unfinished, reporting the best available artifact and never claiming a pass; corrections continue while verification shows evidenced improvement. The button reads Stop Run while a run is active; stopping records unfinished and never replays. Reopening after an interruption shows the run unfinished. Configure Path changes this run's role choices — each tool plus, where deliverable, a named model and effort, or the tool's own configured model — and the two interruption preferences; changes apply to that run only. Settings (footer, beside Help) holds the warning switch, role defaults and the spending preference. A named model is labelled as requested; the model that actually answered is shown only where the tool reports it.

    Readiness of the selected tool is checked in the background without a model call; failures name their own reason, and sign-in or native permissions are resolved in the tool's own window. An action whose required bundled component is missing, incompatible or of unknown compatibility is greyed out with its component, reason and remedy — a missing sign-in never greys an implemented capability, and the readiness details also show each tool's optional Gear primary and peer availability beside the bundled Bridge, Programming Loop and Ora AI Boost versions. A choice that becomes unavailable stays selected and explained; the draft, attachments and project context are preserved, and compatible conversation, stages and Copy stay usable. Recheck refreshes both readiness and discovery after you install, remove, update or sign into a tool. Closing the browser leaves Vibe and external AI work running. Stop Vibe and the Mac's Quit warn when a turn is active or unsent text exists, then interrupt the active turn and record the outcome; files already changed remain. An interrupted turn or run is never replayed automatically.
